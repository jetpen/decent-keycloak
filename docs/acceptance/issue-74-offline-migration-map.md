# Issue #74 lifecycle migration status: offline/local/CI

This is a bounded offline/local/CI slice, not completion of Issue #74. Local instructions and PR workflow invoke the same `keycloakctl acceptance --profile offline` profile. It performs local preflight, repository suites, provider and test-RP image build/smokes, source-bound sanitized receipt, and whitespace checks; offline acceptance retains built images and records cleanup as `not_run`. The RP smoke executes its configured image entrypoint with network access disabled, starts a loopback listener on an ephemeral port, checks a fixed safe response, and shuts down without issuer access. This is startup evidence only, not RP browser/Keycloak or live qualification. Remote lifecycle, qualification, manual evidence, and publication are deferred. Legacy `--allow-live` is not owner approval. No live or remote operation was run. Keep all 10 Issue #74 acceptance criteria open until their specific gates are verified; criterion 5 remains partial for the limited local input-binding subclaim, and criterion 10 remains partial for strict artifact-validation/ownership subclaims.

## Offline artifact-validation slice and #74 criterion status

The public command is `./keycloakctl validate-artifacts --baseline BASELINE.json --projection CASES.json --config RUNTIME.json`. It reads each source as a bounded regular file; parses strict UTF-8 JSON with duplicate-member, float, and non-finite-number rejection; validates baseline, projection, and the existing non-secret runtime-config schema with Draft 2020-12; requires the projection bytes to be exact compact, sorted-key UTF-8 canonical JSON without a BOM or trailing newline; and compares the baseline's config/projection SHA-256 values to the exact supplied bytes. It enforces the fixed #66 ordered `case_ids` list and exact projection map keys. The local-only `./keycloakctl full` command requires `--baseline FILE` and `--projection FILE` together, validates them against the exact config bytes loaded for that invocation before local preflight/build/test, and binds the exact baseline/projection byte SHA-256 values into the immutable `run-intent.json`. The intent stores only hashes, not raw artifacts, caller paths, owner approval, or secrets; changed valid artifacts on resume conflict with the sealed intent without replacing its source manifest or intent. If interrupted after writing the source manifest but before the intent, resume accepts only a canonical manifest matching the current source capture, then completes sealing. The validator itself does not verify the truth of references, authenticate `owner_review_ref`, establish readiness, accept approval, or execute cases. Separately, the local-only `full` path snapshots repository-relative tracked and untracked regular files and contained symlinks after an explicit generated/non-input exclusion list (including the `.gitignore` generated paths `target/`, `/.keycloakctl/`, Python caches, resolver downloads, and materialized sources), recording mode and content SHA-256, then seals that manifest under the run with restrictive permissions and binds its hash/count into the immutable local intent after a second capture agrees. It records link text/mode and hashes each repository-contained regular target through its own manifest entry; absolute, escaping, chained/special, or otherwise unsupported targets fail closed. Ignored-but-nonexcluded build inputs are included. `target/` artifacts remain separately covered by existing build/image artifact fingerprints, not source inputs. The manifest contains no file contents; these source-capture and artifact-binding subclaims do not infer approval, target, scope, windows, readiness, or authorization.

The validator imports `jsonschema` (with `FormatChecker`) at invocation time. The pinned `jsonschema[format]==4.26.0` runtime and isolated-test dependency is hash-locked in the existing `requirements/issue8-oidc.lock`; CI installs that lock via `.github/workflows/acceptance.yml`, and the isolated test setup uses the same lock. Independent verification installed it with `pip --require-hashes` into Hermes scratch under Python 3.11.13; all 11 artifact validation tests and all 86 `scripts.test_keycloakctl` tests passed. The standalone legacy `scripts/lifecycle.py python-tests` command is distinct from `./keycloakctl acceptance --profile offline`, which runs local/offline build, test, and image-smoke stages and writes a source-bound receipt under `target/keycloakctl/acceptance/`. Live operations were not performed; neither focused tests nor the offline profile establish owner authentication, readiness, approval, or live operation.
