# Wallet-login provider security review

## Scope and disposition

This is a source-and-test review of the provider present at integration baseline `48121bec3ac2708b97c4c39240cd85aadf0117e2`, including the merged #4 resolver changes, plus the #9 logging hardening in this worktree. It is an implementation-stage review record, **not an independent third-party audit or production security qualification**. An independent reviewer must review this document and the aggregate changes after the concurrent #5 Registry and #6 Keycloak acceptance work is integrated; neither downstream diff is reviewed here.

The review followed the proof, resolver, browser/session, account, replay/callback, logging, image supply-chain and failure paths in the source files and checked the owning unit tests. The log-stack finding below was fixed with a regression test. No other provider behavior change was made as part of this review. Existing tests and a loopback probe provide bounded evidence only; they do not qualify the real Registry, Keycloak provider/store, browser/TLS/wallet or production behavior.

## Finding fixed in this slice

**Privacy: challenge setup exception disclosure.** `WalletChallengeAuthenticator.authenticate` passed the caught exception to the logger, which emitted its stack trace and message. Because rendering/session failures are near authentication state and error messages are not an allowlisted log schema, that could disclose sensitive context. A failing regression captured a mocked exception containing a private marker and verified the logger record carried the exception; the implementation now logs only the fixed event text while preserving fail-closed behavior. The focused test passes after the fix. No proof, callback, Identity ID or raw exception is added to this diagnostic.
